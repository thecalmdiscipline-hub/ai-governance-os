## 1. Project overzicht

**Valqeron** is een B2B SaaS-platform dat bedrijven helpt AI-systemen gecontroleerd te deployen, besturen en monitoren via een centrale "control layer" (Valqeron Core). Propositie: *gecontroleerde AI in plaats van gefragmenteerde tools* — governance, audit-logging, risicobeheer en 10 kant-en-klare AI-workflows in één omgeving, gepositioneerd richting EU AI Act / ISO 27001 / ISO 42001-compliance.

- **Doelgroep:** B2B, met name bedrijven vanaf €1M+ jaaromzet die operationele AI-automatisering willen met oversight (zie ICP-tekst in `app/workflows/implementations/sales_lead_qualification.py:37`).
- **Stack:** FastAPI + PostgreSQL (prod) / SQLite (dev/test) + OpenAI (`gpt-4o-mini`). Multi-tenant via `organization_id` op elke tabel (single-tenant-per-organisatie isolatie, geen aparte databases).
- **Frontend (oud, gepensioneerd 2026-09-18):** React 18 via CDN (Babel standalone, geen build tooling), was geserveerd als static files door FastAPI. `app/static/app.jsx` — dit was de marketing/product-SPA op `app.`/`api.`/`compliance.valqeron.com`. De bestanden staan nog in `app/static/` als referentie maar worden nergens meer geserveerd.
- **Frontend (nieuw, klantportaal, live sinds 2026-09-18):** `ai-governance-frontend` — apart Vite + React 19 + TypeScript-project op de Mac (`/Users/dennisschetters/ai-governance-frontend`; sinds 2026-09-20 eigen private repo `thecalmdiscipline-hub/ai-governance-frontend` met CI/CD, zie sectie 2), gedeployed als static build (`npm run build` → `dist/`) naar `app.valqeron.com` via nginx (los van de FastAPI-backend). Praat cross-origin met de backend via `VITE_API_BASE=https://api.valqeron.com`. Zie sectie 2/4/6 voor de deploy-status.

### Handleiding: een klant aanmaken (in gewoon Nederlands)

Je hebt twee manieren. Beide maken in één keer een organisatie, een eerste beheerder, de gekozen modules, een standaard-AI-beleid, per workflow een AI-systeem met een eerste risico, en op verzoek een voorbeelddocument. De beheerder krijgt een eenmalig wachtwoord (nooit per e-mail versturen; geef het via een veilig kanaal) en moet het bij de eerste keer inloggen veranderen.

**Regels voor de modules (`tier`):** `core` is altijd nodig en telt niet mee. *Starter* = minstens 2 workflows; *Business* = minstens 5 workflows, waaronder `compliance_monitor`; *Enterprise* = minstens 7 workflows, waaronder `compliance_monitor`. De 10 workflows zijn: `document_intelligence`, `compliance_monitor`, `customer_support_ai`, `sales_qualification_ai`, `invoice_processing_ai`, `hr_recruitment_ai`, `marketing_automation_ai`, `meeting_agenda_assistant`, `quote_contract_generator`, `business_intelligence`.

**Manier 1: op de server met het script** (handig voor een demotenant of de ISO Cert-organisatie). Zet een bestand `klant.json` op de server, bijvoorbeeld:

```json
{
  "idempotency_key": "voorbeeld-bv-2026-09",
  "organization_name": "Voorbeeld B.V.",
  "country": "NL",
  "sector": "Dienstverlening",
  "tier": "starter",
  "modules": ["core", "customer_support_ai", "document_intelligence"],
  "admin_username": "voorbeeld_admin",
  "admin_email": "beheer@voorbeeld.nl",
  "include_demo_document": true,
  "include_demo_run": false
}
```

Dan: `ssh root@164.92.221.90`, `cd /opt/valqeron`, eerst kijken wat er zou gebeuren: `venv/bin/python scripts/provision_tenant.py --config klant.json --dry-run`, daarna echt: `venv/bin/python scripts/provision_tenant.py --config klant.json` (het wachtwoord staat dan één keer op het scherm) of `... --password-file /root/voorbeeld-wachtwoord.txt` (het wachtwoord gaat dan naar een nieuw bestand dat alleen root kan lezen; verwijder het bestand na het doorgeven). Draai je hetzelfde bestand nog een keer, dan gebeurt er niets (en krijg je geen wachtwoord meer). `idempotency_key` moet voor elke nieuwe klant uniek zijn.

**Manier 2: via de API** (`POST https://api.valqeron.com/ops/tenants/provision`, zelfde velden). Daarvoor heb je een **ops-token** nodig: log in met je wachtwoord (`POST /login`, veld `username` en `password`) — dat geeft een `mfa_token` — en daarna met je 6-cijfercode (`POST /login/mfa` met `{"mfa_token": "...", "code": "123456"}`); het `access_token` in het antwoord is je ops-token (60 minuten geldig). Met `OPS_TOKEN=<dat token> BASE_URL=https://api.valqeron.com bash scripts/smoke_provision.sh` maak je een proefklant om de hele keten te controleren (dat script maakt zelf geen tokens). Modules van een bestaande klant wijzig je met `PUT /ops/tenants/{id}/modules` (body `{"tier": "...", "modules": [...]}`), en `GET /ops/tenants` toont alle klanten.

**Procesnotitie:** backend en frontend deployen zichzelf bij elke push naar `main` (CI groen → Deploy); `deploy.sh` schrijft `BUILD_SHA` maar synct de systemd-unit niet (zie `DEPLOY_RECOVERY.md`). Wegwerp-productietests: server-side script met pacing (≥13 s tussen logins), tokens alleen in geheugen. Parallel: DPA via de jurist (nu ook Sentry). Blijf vóór elke CLAUDE.md-wijziging `git status`/`git diff` doen en na de commit verifiëren dat de wijziging blijft staan.
