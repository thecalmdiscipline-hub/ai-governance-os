## 1. Project overzicht

**Valqeron** is een B2B SaaS-platform dat bedrijven helpt AI-systemen gecontroleerd te deployen, besturen en monitoren via een centrale "control layer" (Valqeron Core). Propositie: *gecontroleerde AI in plaats van gefragmenteerde tools* — governance, audit-logging, risicobeheer en 10 kant-en-klare AI-workflows in één omgeving, gepositioneerd richting EU AI Act / ISO 27001 / ISO 42001-compliance.

- **Doelgroep:** B2B, met name bedrijven vanaf €1M+ jaaromzet die operationele AI-automatisering willen met oversight (zie ICP-tekst in `app/workflows/implementations/sales_lead_qualification.py:37`).
- **Stack:** FastAPI + PostgreSQL (prod) / SQLite (dev/test) + OpenAI (`gpt-4o-mini`). Multi-tenant via `organization_id` op elke tabel (single-tenant-per-organisatie isolatie, geen aparte databases).
- **Frontend:** React 18 via CDN (Babel standalone, geen build tooling), geserveerd als static files door FastAPI. `app/static/app.jsx`.

### Pricing (3 tiers) — bron: `app/static/app.jsx:112-208`, ongewijzigd t.o.v. analyse van 2026-05-15

## 4. Openstaande kritieke acties (prioriteitsvolgorde)

Volgorde is een inschatting op basis van wat er in de code ontbreekt en wat sales/compliance blokkeert. Tijdsinschattingen zijn indicaties, geen harde toezeggingen — pas aan waar je betere info hebt.

0. **🔴 KRITIEK, actief live — `app.valqeron.com` toont een lege/kapotte pagina aan elke bezoeker**
   Status: root cause gevonden en gefixt in de repo op 2026-09-13, **nog niet gedeployed naar de server**.
   Wat er mis is: `nginx/sites/app.valqeron.com.conf` had een Content-Security-Policy-header (`script-src 'self'`) die de CDN-scripts blokkeert waar `app/static/index.html` van afhangt (React, ReactDOM en Babel-standalone via unpkg.com) — bevestigd via de browserconsole ("violates ... script-src 'self' ... blocked") tijdens een live check op 2026-09-13. Resultaat: de React-app rendert nooit, bezoekers zien een lege pagina. `compliance.` en `api.valqeron.com` hebben deze header niet en werken wel gewoon (zelfde `app.jsx`, zelfde content, live gecontroleerd). `valqeron.com` (kale domein) draait trouwens ook al op dezelfde app/`app.jsx` en werkt ook prima — de eerdere aanname in dit document dat de kale domeinnaam nog los op Apache/IONOS staat, klopt dus niet (meer); zie de gecorrigeerde rij in sectie 2.
   Fix: de CSP-header aangepast naar `script-src 'self' https://unpkg.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com;` (precies wat `index.html` daadwerkelijk laadt, inclusief Google Fonts die dezelfde header ook blokkeerde). Bestand is al aangepast op de Mac; moet nog gedeployed worden (server-toegang ontbreekt vanuit deze sessie — zie sectie 2/openstaande toegang).
   Nodig: iemand met serverd toegang draait `scripts/deploy.sh` (of kopieert het bestand en herlaadt nginx: `nginx -t && systemctl reload nginx`) om de fix live te zetten. Kleine moeite, grote impact — dit blokkeert feitelijk elke demo of bezoeker die specifiek naar `app.valqeron.com` gaat.
